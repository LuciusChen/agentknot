# Changelog

All release-relevant changes to AgentKnot are recorded here. The project follows semantic versioning once versions are intentionally published; commits to `main` are not releases by themselves.

## [Unreleased]

Entries in this unreleased history retain earlier implementation evidence; the `Removed` section below records the current built-in surface.

### Added

- Minimal WorkOrder-rooted developer task CLI. `agentknot task` issues an immutable WorkOrder, admits one ordinary Executor Job through the existing Job API, explicitly binds its durable identity, waits for terminal evidence, verifies recorded artifacts, and prints a human completion report with intent, technical status, summary, changed paths, worker-reported checks, integrity outcome, and next action. Default `task` and `task-show` output omits internal IDs, artifact paths/hashes, and raw records; explicit `--json` retains the complete WorkOrder, Job, and verification evidence for machines. `task-show WORK_ORDER_ID` reopens the same WorkOrder and Job stores after process restart. This is a controller-side composition over existing records: it adds no Task, Candidate, Review, or Disposition record, does not change WorkOrder/Job/Orchestration status, and does not apply or promote artifacts. Job admission and WorkOrder binding remain separate transactions.

- First-class durable WorkOrders above technical execution. `WorkOrderService.issue` persists an immutable schema-versioned command and `work-order.issued` event in one SQLite transaction. `bindExecutorJob(workOrderId, expectedWorkOrderRevision, executorJobId)` explicitly records one caller-admitted executor Job identity through WorkOrder CAS and one append-only `work-order.executor-job.bound` event; same-Job replay is idempotent, while stale first binding or a different Job conflicts. The operation does not admit, launch, cancel, recover, or otherwise control the Job, and Job success is not WorkOrder acceptance. CandidateRecord, ReviewRecord, and the later DispositionRecord are separate explicit domain evidence/decision records.

- Minimal immutable, status-free `CandidateRecord` API. `CandidateService.create` validates a persisted WorkOrder is bound to the requested Executor Job and that the Job records one exact `git-patch` artifact identity (`path`, `sha256`, `baseCommit`), then atomically persists the Candidate snapshot and `candidate.created` event through `SqliteCandidateStore` and the existing durable SQLite/event infrastructure. The validation reads and Candidate write are separate stores, not one cross-store transaction; the service never reads, hashes, copies, or applies patch bytes and never changes WorkOrder/Job records or statuses. The surface is TypeScript-only and adds no Candidate CLI, Review, Disposition, acceptance, promotion, or application behavior.

- Minimal immutable, schemaVersion 1, status-free `ReviewRecord` API. `ReviewService.create` performs a read-only existence check for one CandidateRecord, then atomically persists one Review snapshot and one `review.created` event through `SqliteReviewStore` and the existing durable SQLite/event infrastructure. The record retains bounded non-empty reviewer identity and summary plus defensively copied findings with independent low/medium/high severity, message, and evidence fields; it has no verdict, recommendation, acceptance/discard value, lifecycle status, or `updatedAt`, and multiple Reviews may reference one Candidate. Candidate validation and Review persistence are separate stores without cross-store transaction, recovery, or reconciliation. Existing orchestration quality-review evidence is a separate contract and is never converted; the TypeScript-only surface adds no CLI/HTTP workflow, Disposition, acceptance, discard, artifact application, commit, merge, push, or promotion behavior.

- Minimal immutable, schemaVersion 1, status-free `DispositionRecord` API. `DispositionService.record` validates one existing Candidate and one belonging Review through separate read-only stores, then `SqliteDispositionStore` atomically persists one fixed-length Candidate-derived identity and `disposition.recorded` event. The first accept/discard decision succeeds, exact semantic replay is idempotent without a second event, and any different review ID, decision, decider, or rationale conflicts, including concurrent independent-store races. The record never applies, promotes, commits, merges, pushes, deletes, or otherwise mutates Candidate artifacts or the canonical workspace; no CLI/HTTP or automatic disposition path is added, and Job success is not acceptance.

- Fixed-shape per-attempt downstream usage evidence. Every completed worker attempt now persists either exact token totals plus provider-reported cost or an explicit unavailable reason before artifact/terminal transitions. Settled Pi errors query statistics once before exact-child shutdown; pre-settlement and lease-lost recovery attempts record `worker-failure`; policy-rejected results retain their consumption; retries aggregate every attempt once; and successful legacy Jobs retain terminal-metadata fallback without double counting. Human usage coverage is now available/observed attempts; controller usage, quota inference, price normalization, route/model branches, and full repeated session-stat blobs remain absent ([decision 0086](postmortems/0086-per-attempt-usage-evidence.md)).

- Experimental selective same-workspace context references. `ContextReference.kind: "workspace-file"` accepts only portable repository-relative locators and tells workers to read a task-relevant subset with their existing tools; every other locator remains metadata-only, and no new reader, adapter API, memory service, repository scan, or automatic reference generation is added. Final hidden-oracle A/B batches kept exact quality with one target read and no decoy reads while reducing provider-reported total tokens by 30.13% on DeepSeek Flash/max and 32.66% on Luna/max. Both batches failed the complete promotion gate because latency rose 26.47% and 53.07%, and Luna's input-plus-cache-read-plus-output rose 298.77%, so the capability remains explicit and experimental ([experiment/decision 0081](postmortems/0081-selective-workspace-context-ab.md)).

- Three serial real Luna/max quality-review A/B trials compared prompt-embedded verified patches with exact on-demand artifact reads across two valid patches and one seeded defect. No trial cleared the predefined 3/3 reliability and efficiency gate; across the five complete pairs the read-grant arm won reported total tokens in only two, used 8.7% more total tokens and 17.8% more input-plus-cache-read-plus-output, and was 4.8% slower descriptively. The capability remains for exact authority and auditability, with no token-efficiency claim or expansion to other context-reference kinds. The one-off runner was deleted after evidence capture instead of becoming product surface ([experiment/incident 0080](postmortems/0080-artifact-read-review-ab.md)).

- Exact single-use artifact-read grants for bounded advisory review. A durable Job grant carries only one recorded Git-patch identity whose exact bounded size is its byte ceiling; every attempt resolves the same terminal source Job in the same workspace, rechecks identity and integrity/base evidence, persists a content-free read event before serving, fails closed without retry on missing/stale evidence, and rejects adapters that complete without a served read or suppress a refusal. Quality-review prompts no longer embed patch bytes. The generic `WorkerRunInput` reader remains worker-neutral; Pi maps it to one explicitly loaded product extension over an attempt-owned child-process IPC channel, requests bytes only when the tool is invoked, keeps the required tool active in attempt-local filters without mutating configuration, creates no artifact-content temporary file, and sanitizes tool arguments/results before persistence. `ContextManifest` locators remain unverified metadata and no token-savings claim is made before A/B evidence ([decision 0078](postmortems/0078-exact-artifact-read-grant.md)).

- External-target ancestor isolation for managed worktrees. Relative `workspaceIsolation.directory` values now identify a stable private platform-temporary namespace rather than placing every target beneath the runtime/config repository. This prevents worker context discovery and validation/package tools from walking into an unrelated host project's `AGENTS.md`, `package.json`, or configuration. Absolute roots remain exact and attempt cleanup remains identity-bound ([incident/decision 0079](postmortems/0079-external-worktree-ancestor-isolation.md)).

- Bounded MCP orchestration waiting over the existing durable cursor. One `agentknot_orchestration_wait` call applies one default 40-second wait-phase deadline to the initial exact-ID snapshot and subsequent event batches, returns terminal evidence or the same orchestration ID and the sequence actually advanced by completed follow batches for idempotent reattachment, propagates cancellation without cancelling durable work, and emits standard progress only when the controller supplies a progress token. Deadline expiry issues no fallback read and does not acknowledge newer events seen only in the initial snapshot. The one-batch follow tool remains diagnostic; detached controller notification remains gated on a supported controller resume entry ([incident/decision 0075](postmortems/0075-bounded-mcp-wait-and-resume-gate.md)).

- Durable FIFO capacity admission shared by direct, child, and reviewer Jobs under the configured `maxConcurrency`, plus bounded attempt-bound `steer`/`follow-up` with durable accepted/rejected/lost evidence. Lease reclaim atomically preserves an acquired capacity row, asynchronous local fallback admission remains FIFO, terminal Job state cannot pass an unsettled control request, late Pi RPC control responses are quarantined from the main worker result, and HTTP clients reject control capabilities or receipts whose exact request identity differs. Graceful close releases the listener even when drain fails and releases runtime ownership only afterward. The production lifetime lock remains until a separate multi-executor protocol is delivered; no controller planning, cross-Job chat, message replay, or provider fallback is added.

- Identical stateless controller-entry `SessionStart` hooks for Codex and Claude on `startup`, `resume`, `clear`, and `compact`. Each hook reads only bounded event JSON and emits one concise controller obligation without filesystem, Git, network, broker, policy, runtime, prompt, transcript, or session-state work; no `UserPromptSubmit` hook exists. Codex implicit-invocation metadata remains only a selection hint: a real fresh-session miss showed that it does not prove automatic Skill invocation. After the correction, one fresh Codex repository-analysis prompt that did not mention AgentKnot selected the Skill, admitted a strict assessment through the existing broker, and completed one Pi/OpenCode Go/Luna/max child with the required report and verified empty artifact. The controller still owns semantic eligibility and planning, AgentKnot remains independent middleware, and real Claude parity remains open ([incident/decision 0074](postmortems/0074-session-start-controller-entry.md)).

- Compact route-neutral worker activity on existing cursor waits. The additive projection derives lifecycle state, explicit evidence coverage, last-observation age, and bounded sanitized active-tool names from already durable events without copying prompts, worker text, stderr, raw frames, tool call IDs, arguments, or results. Pi RPC coalesces consecutive text frames before the fixed event budget while preserving exact output and non-text ordering; a real DeepSeek V4 Flash/max audit retained 42 events from 6,311 raw frames with no truncation and a complete terminal envelope ([incident/decision 0072](postmortems/0072-compact-worker-activity-and-pi-frame-coalescing.md)).

Its summary, unique repository-relative initial paths, and constraints are strictly validated within 2 KiB, copied into admitted evidence and the plan hash, and projected identically before each child-specific prompt. Controller Skills build it only from existing conversation facts and omit it instead of scanning; no transcript, fixed worker session, memory service, route/model choice, or provider-cache dependency is added ([incident/decision 0068](postmortems/0068-bounded-shared-task-context.md)).

Bounded metadata carries identity, kind, opaque locator, actual source, explicit unverified trust, and optional revision, SHA-256 digest, and summary; strict validation, defensive copies, aggregate 2 KiB enforcement, plan hashing, deterministic one-time prompt projection, and MCP admission are covered without resolving references or adding a memory/provider/session dependency ([decision 0077](postmortems/0077-task-context-reference-manifest.md)).

Same-process readers wake only after a successful commit, reconnect from an acknowledged sequence, and retain a durable refresh fallback across broker/process replacement. ### Changed

- Normal Pi Jobs now load one product-owned ephemeral `tool_result` limiter after configured extensions. Text returned to the next model call is capped at 8 KiB with valid UTF-8 and explicit truncation evidence; Bash retains its tail while read/search-like tools retain their head, and multiple text blocks share the same aggregate bound. The exact `agentknot_artifact_read` capability is exempt so review authority is not silently truncated. A same-task Luna/max probe reduced provider-reported total tokens by 15.1% and cost by 23.9%, while latency increased 35.5%; this is one bounded-context result and a deterministic safety limit, not a universal efficiency claim ([incident/decision 0088](postmortems/0088-bound-pi-tool-result-context.md)).

- Whole-Job retries for structured pre-settlement worker failures now persist their route-neutral reason and bounded delay in `job.retrying`, then wait with one-second-based exponential backoff and deterministic per-Job jitter before starting the already reserved next attempt. Adapter-supplied structured retry delay hints are honored within a 60-second ceiling, cancellation interrupts the wait, and Pi process exit before `agent_settled` uses this contract. Settled worker errors remain terminal and no provider strings, quota state, model fallback, route switching, recovery, or lifecycle semantics were added ([incident/decision 0087](postmortems/0087-pre-settlement-worker-retry-backoff.md)).

- Kept automatic candidate-reference generation out of the controller handoff after a real AgentKnot repository probe. Against a 28,487-token / 18.137-second `relevantPaths` arm, generic and role-summary `workspace-file` variants used 30,069 (+5.55%) and 35,100 (+23.21%) tokens and were 22.70% and 39.68% slower; all answers were semantically correct, but ordinary workspace tools still searched or read multiple candidates and exact JSON-only output was not preserved. The uncommitted default-contract draft was removed. As a deterministic upstream fixed-input reduction, the representative Codex Skill shrank from 5,600 bytes / 704 words to 5,005 / 607 while the normalized Claude body remained equivalent, and the lifecycle obligation fell from 1,001 characters / 127 whitespace-delimited words to 752 / 96 with an 800-character cap. A fresh isolated `gpt-5.6-sol`/low Skill-load pair subsequently reduced Codex-reported input from 33,042 to 32,878 tokens (-164, -0.50%) with identical 25,088 cached input. AgentKnot installs no operating-system service or shell configuration; `broker run` may be hosted by an external supervisor, while explicit `broker up` uses only application process primitives ([decision 0057](postmortems/0057-independent-broker-and-thin-controller-clients.md)).

### Fixed

- Missing or invalid Pi completion envelopes no longer cause immediate full Job replay after the task turn has already settled. The adapter now requests the strict envelope once through a new `prompt` in the same idle Pi process/session, records only bounded `completion-envelope` recovery progress, and either succeeds on the same Job attempt or terminates non-retryably after a second invalid settlement. Assistant errors bypass recovery and pre-first-settlement failures keep their existing retry behavior. Installed Pi source review corrected an initial fake-fixture assumption that idle `follow_up` would start a turn; a forced real route trial then exposed and fixed the missing cross-turn text delimiter before succeeding at attempt one with a complete persisted report ([incident/decision 0085](postmortems/0085-in-session-completion-envelope-recovery.md)).

- Worker retry ownership after three real Luna/max dogfood reviews each exhausted Pi's context-preserving downstream retry and were then replayed as a second full AgentKnot attempt. Adapters may now throw route-neutral `WorkerSettledError` after their own downstream policy settles failed; the orchestrator terminates that Job without replay, while pre-settlement process/protocol/transport failures retain configured whole-worker attempts. Normalized/compact activity reports safe downstream retry scope and progress without raw error text, provider parsing, quota inference, or route fallback ([incident/decision 0084](postmortems/0084-worker-settled-retry-ownership.md)).

- Controller-authored explicit output formats now take precedence over the generic orchestration footer's files/checks/risks prose request. The first selective-context A/B batch reproduced correct strict JSON followed by extra prose or duplicated JSON; the shared route-neutral prompt contract was corrected without a controller, worker, provider, model, or task-kind branch ([experiment/decision 0081](postmortems/0081-selective-workspace-context-ab.md)).

- Worker completion now defines `taskOutcome` against the assigned worker-role task rather than the acceptability of an inspected subject. A completed advisory review therefore reports `completed` even when its verdict requests changes; `blocked` remains the non-retryable result only when the assigned review itself could not be performed. Real A/B negative controls reproduced the former contradiction in both artifact-delivery arms and then passed with `changes-requested` after the shared, adapter-neutral instruction was corrected ([experiment/incident 0080](postmortems/0080-artifact-read-review-ab.md)).

- Sparse-checkout worktrees no longer turn every unmaterialized tracked path into a false deletion during artifact capture. The temporary artifact index now preserves the managed worktree's Git `skip-worktree` state without expanding the checkout or mutating the source. Delegated `repository-analysis` Jobs that nevertheless write files retain the captured artifact but fail once with a route-neutral, non-retryable read-only violation; artifact integrity remains distinct from task completion and semantic compliance ([incident 0070](postmortems/0070-sparse-worktree-artifact-boundary.md)).
- Pi RPC now maps only canonical `tool_execution_start` frames to `worker.tool.started`; the preceding assistant `message_update/toolcall_end` no longer creates a duplicate start event. Recent real Jobs showed an exact 2:1 started/completed pattern before the fix, inflating durable event volume and causing earlier record truncation without representing additional work ([incident 0066](postmortems/0066-pi-duplicate-tool-start-events.md)).
- Failed or losing `broker up` startup attempts now supervise the exact spawned child through bounded `SIGTERM` → `SIGKILL` cleanup and confirm its exit before returning an error or reusing another broker. A real-child regression covers a readiness timeout whose detached child ignores `SIGTERM`; no OS service, shell mutation, or controller-entry hook is involved in broker startup, and no platform-specific transport is introduced ([incident 0064](postmortems/0064-broker-startup-child-cleanup.md)).
- Git worktree artifact capture now preserves tracked-file deletions. Intent-to-add discovery ignores removals before the worker-delta diff, so deleted paths remain in both the patch and controller-derived `changedFiles`; a mixed tracked/untracked/binary regression applies the captured deletion cleanly ([incident 0060](postmortems/0060-artifact-capture-omitted-deletions.md)).

Lifecycle settlement and the required completion envelope remain strict; unusable accounting is retained as advisory `sessionStats.unavailableReason: "invalid"` evidence instead of a terminal worker error ([incident 0056](postmortems/0056-opencode-statistics-advisory-boundary.md)).
- Accepted durable cancellation can no longer be overwritten by a simultaneous success transition. Explicit lease release retains an inactive fence tombstone so the next claim cannot reuse an old generation, failed first-lease admission cannot leave a queued/idempotent orphan, and legacy JSON import rejects filename/payload identity mismatches ([decision 0055](postmortems/0055-durable-middleware-kernel.md)).
- Graceful HTTP shutdown no longer drops the listener while storage locks and active work are still owned. It rejects new Job/orchestration admissions with 503, keeps liveness/read access available while admitted work cancels and drains, then closes the listener before runtime ownership is released; response-stream failures are connection-local ([incident/decision 0046](postmortems/0046-clutch-review-listing-and-shutdown-gaps.md)).

Empty patch verification stays valid artifact evidence but never proves task completion. Managed worktree names also use the existing `job_...` identity exactly once instead of producing `job-job_...` paths ([incident/decision 0044](postmortems/0044-required-worker-completion-and-canonical-worktree-id.md)).
